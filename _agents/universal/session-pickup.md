# Session pickup — cross-harness conversation recovery (C4)

Part of the universal agent set (core: `_agents/universal_agent_instructions.md`). On loading this file, announce it with one visible line: `loaded: _agents/universal/session-pickup.md`. Load when the user says "pick up where Claude left off," "pick up where Codex left off," "continue/examine the latest Claude/Codex chat," or equivalent — that phrasing is explicit authorization to read the named harness's local transcript. Search the harness's native session store FIRST — never assume a repository folder named `conversations/` contains harness transcripts unless the user or project instructions explicitly say so.

**Search order and selection — mandatory:**

- Resolve the current repository's canonical absolute path and the real interactive user's home directory. Do not blindly trust `$HOME` / `USERPROFILE`, because a sandbox may run under a service account. If necessary, inspect user profiles for a `.claude` or `.codex` store containing transcript metadata whose `cwd` matches the repository.
- **Claude Code:** search `<USER_HOME>/.claude/projects/<encoded-project-path>/`. On Windows this is typically `C:\Users\<user>\.claude\projects\<encoded-project-path>\`. Main conversations are top-level `*.jsonl` files directly inside that project directory. Exclude nested `<session-id>/subagents/`, `*.meta.json`, memory files, locks, and `history.jsonl`. Validate candidates through their normalized `cwd`, require `isSidechain != true`, and select the newest substantive main-session message timestamp; use file modification time only as a fallback.
- **Codex:** search `<CODEX_HOME>/sessions/YYYY/MM/DD/rollout-*.jsonl`, where `CODEX_HOME` defaults to `<USER_HOME>/.codex`; also check `<CODEX_HOME>/archived_sessions/` when necessary. Read each candidate's initial `session_meta` record, require normalized `payload.cwd` to match the repository and `payload.thread_source == "user"`, and exclude `payload.thread_source == "subagent"`. Prefer top-level IDs listed in `<CODEX_HOME>/session_index.jsonl`; rank by `updated_at`, then transcript message timestamp, then file modification time.
- Never select a transcript solely because it is the newest file. Reject bootstrap-only or empty sessions and subagent transcripts. If the selected main transcript references a task notification, background agent, or output file, read that linked artifact only as needed to reconstruct the parent conversation.
- Read backward from the end until the last substantive human request, completed work, tool/test/device results, changed files and commits, and the exact unfinished step or blocker are all understood.
- Cross-check transcript claims against current `git status`, recent commits, `HANDOFF_FILE`, the State file, and the newest Build Log entries. Git and filesystem state determine what actually landed.
- Before proceeding, identify the selected harness, session ID, and timestamp, then give a concise pickup checkpoint. Never expose credentials, tokens, secrets, or other sensitive transcript contents.
- If the user said **"examine,"** report findings without making changes. If the user said **"pick up"** or **"continue,"** resume the unfinished user-approved task within its existing scope and permission boundaries.
- If no matching transcript exists, report the exact native stores checked and fall back to the repository's handoff/reference files. Do not silently substitute `conversations/`.

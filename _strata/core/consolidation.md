# Semantic consolidation

Use this procedure when documentation contains duplicated, overlapping, stale, or conflicting claims.
Its purpose is one clear current truth, not shorter files at any cost.

1. Identify each claim and its owning authority.
2. Compare meaning, scope, conditions, evidence, and time—not merely similar wording.
3. Classify the relationship:
   - exact duplicate: retain one current claim;
   - superseded: retain the newer governing claim and remove the obsolete live claim;
   - narrowed or corrected: retain the precise formulation and remove the misleading broad one;
   - same claim or obligation, different objects: when one covers the other—stating or performing it
     necessarily satisfies the other for every object the other names—retain the covering one with its
     wording unchanged, extend its object list with the objects the other carried, each phrase copied
     verbatim, and remove the absorbed one. Never replace enumerated objects with a broader category,
     never compose a predicate neither stated, and never absorb across two authority files, because a
     file's audience is part of what its claims assert;
   - complementary: retain both without forcing a merge—reach for this only after the preceding case,
     because two claims imposing the same obligation on different objects are not complementary;
   - a still-true description of current behavior: record it as a dated observed snapshot in Build Log
     rather than leaving it in a retired document;
   - unresolved conflict: surface the competing claims and ask the user rather than choosing precedence.
4. Preserve useful evolution as a compact Rationale explanation or Build Log history when it still helps
   future decisions. Historical context must not remain as a competing current rule.
5. Repair inbound references, affected checks, and indexes.
